# 设计

`dataminePolyfill` 只做解析；取数、裁剪、缓存与生成由同一次解析完成。

## 在 resolveId 里回答

插件把回答放在 `resolveId`，并声明 `enforce: 'pre'`。这个说明符不在本包的 `exports` 里，也不在磁盘上，vite 自己的解析器一定会失败；`pre` 让它排在别名与核心解析之前。

## 真实文件

返回缓存里的真实文件，而不是 `\0` 虚拟模块。调试时那个文件可以直接打开看数据，下游也不需要知道模块是合成的。

## 扩展名

生成物用 `.js` 而不是 `.json`。后缀决定谁会处理这个文件，而生成物带的是 `export default`。

## 只有数据

模块内容是 `SheetRawData` 的 JSON，前面一行 provenance 注释。读取由 `xiv-datamine-provider` 的 `useSheetTable` 完成，本包不带运行时代码进产物。

裁剪只按列名、`#` 值与空值声明，不引入“这一列是布尔”之类的类型知识，也没有逐表登记例外的必要。

## 内容哈希

模块名必须包含 CSV 内容哈希，否则移动的 `HEAD` 会命中上一次留下的模块，构建读到旧数据还以为是新的。

## 不清理

同一次构建里两个入口用不同规则导入同一张表是合法的，按“同名新键”删除会删掉另一个入口还在用的文件，所以缓存不清理旧文件。

## 读取顺序

先读 CSV 再查模块，是为了让内容哈希进入模块名。代价是每次构建都要读一遍 CSV，换来的是模块命中时跳过解析与裁剪。

## 传输

`fetch` 默认用全局函数。代理由调用方传入配好的 `fetch`；本包不引 proxy agent，也不调外部命令。

不查 GitHub 的 release 列表。raw 主机按 ref 名服务，省掉一次 API 调用、限流与发版滞后。
