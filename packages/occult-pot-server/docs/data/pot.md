# Pot 数据

「罐子」（pot）是魔法罐刷新时间表里的一行。

## 表格的列

智能表的 `values` 以列标题为键，API 侧使用下表的字段名：

| 列标题             | API 字段           | 规则                                                   |
| ------------------ | ------------------ | ------------------------------------------------------ |
| `区服`             | `world`            | `鸟`、`猫`、`猪`、`狗` 之一                            |
| `地图`             | `map`              | `北岛` 或 `南岛`                                       |
| `ID`               | `potId`            | 形如 `54-1-4000E8F3`，即 `^\d+-\d+-400[0-9A-Fa-f]{5}$` |
| `北罐刷新时间`     | `northRefreshAtMs` | 13 位 epoch 毫秒，`0` 视为无效                         |
| `最后一次进岛时间` | `lastVisitAtMs`    | 13 位 epoch 毫秒                                       |

时间在表格里按 UTC+8 显示，存储与传输使用 epoch 毫秒。写入文本列时必须使用带类型的单元格（如 `[{"type":"text","text":"鸟"}]`），裸字符串会被上游丢弃；读取时文本列可能是带类型的单元格、裸字符串或链接单元格，两列时间可能是字符串或数字，服务都会归一处理。

表里另有 `罐子在什么时间刷新`、`罐子还有多久刷新`、`上次进岛时间（几分钟前）` 三列，由表格公式计算，只供人阅读：不存储、不写入，也不出现在任何 API 响应里。

## 刷新周期

罐子的刷新周期是常量 C = 1804 秒（30 分 04 秒）：同一个罐子的北罐刷新时刻构成间隔为 C 的等差序列；同一座岛上，一轮里的南罐比北罐晚 C。

服务只原样存储与返回 `北罐刷新时间`，不计算排期，也不推断下一次刷新时刻。

## 清洗规则

唯一行键是 `区服|地图|ID`，由服务端强制执行：

| 情况                                                                    | 处理方                                                 |
| ----------------------------------------------------------------------- | ------------------------------------------------------ |
| `区服` / `地图` / `ID` 不合规，或 `北罐刷新时间` 为 `0`、缺失、格式不对 | 服务端：读取时从表里删除，永不返回                     |
| `最后一次进岛时间` 超过 `OPS_UPSTREAM_STALE_AFTER_MS`（默认 3 小时）    | 服务端：同上，视为过期                                 |
| 同一个区服、地图与 ID 的组合出现多行                                    | 服务端：读取时只保留 `最后一次进岛时间` 最大的那一行   |
| 上传的罐子在表里已经有同一个键的行                                      | 服务端：更新那一行（并删除同键的其余行），不新增第二行 |

前两类行在读取整张表之后被删除，并记录一条日志；删除失败时下一次读取再试。第三类只在返回与缓存里折叠成一行，一次读取不会删表：同键的其余行由**下一次写入**清理——更新命中的那一行成功之后，再删掉其余。未过期的行照原样返回。

## 文档侧元数据

缓存里的每一条是 `PotRecord`：五个字段加上 `docs`（`{ recordId, createTime, updateTime }`），记录它在表里是哪一行、以及本地什么时候写过它。两个时间戳都是**本地写入时刻**的 epoch 毫秒：新增时 `createTime = updateTime = now()`；更新时保留该行已有的 `createTime`，只把 `updateTime` 推到本次写入。腾讯文档自己的 `createTime`/`updateTime` 只在[查询记录](https://docs.qq.com/open/document/app/openapi/v2/smartsheet/record/get_records.html)里返回，新增与更新接口都不回传，因此不能作为这两个字段的来源。

`docs` 只在写入成功时更新：上游拒绝写入时，表、缓存与 `docs` 都不变。`docs` 不进入任何 API 响应——调用方只看到 `Pot` 的五个字段。

过期判定的阈值（默认 3 小时）是 `OPS_UPSTREAM_STALE_AFTER_MS`，取值见 [配置：出站调用](../config/upstream.md)。
