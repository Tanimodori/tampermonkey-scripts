# 存储设计

罐子列表、腾讯文档凭据与调用者的访问计数都放在 Redis 里；腾讯文档在线表格始终是数据的权威来源。

## 缓存

- 缓存未超过有效期时，读取请求直接使用缓存；超过有效期才读取腾讯文档，读到的整份列表替换缓存。
- 读取腾讯文档失败时，只要缓存中有数据就返回缓存内容并记录一条 warning；缓存为空时把失败返回给调用方。
- 写入是一次 upsert：先读一次表（表的权威性高于可能落后的缓存），命中唯一行键（`区服|地图|ID`）就更新那一行，没命中才追加。写入成功后再把这条记录折进缓存，因此写入后的列表读取能看到它且不会回源；腾讯文档拒绝写入时请求失败，表与缓存都不变。
- 缓存按唯一行键去重，也按同一个键**替换**：同一个罐子提交两次更新同一条，不会变成两条。
- 缓存里存的是 `PotRecord`（`Pot` 加 `docs`，见 [Pot 数据](pot.md)），并且**只有写入成功时**才更新那一条的 `docs`。
- 回源期间的写入会等待本次回源结束，避免两边互相覆盖。

## 状态与多实例

凭据存放在 Redis 中，因此刷新得到的 token 在进程重启后继续有效；凭据的来源与轮换见 [与腾讯文档通讯](../api/upstream.md)。调用者的访问计数按客户端 IP 记录，探针请求不计入；限流计数也在 Redis 中，多实例共享同一份窗口。

重启不丢数据，多副本看到同一份罐子列表，写入不需要跨实例协调。出站调用队列是每进程一份，多副本会成倍放大腾讯文档的调用量，因此部署建议单实例。
