# 缓存

每张表先取得 CSV，再用表名、`ref`、语种、CSV 内容与规则算出模块文件名。模块文件存在且能解析时复用，否则重新生成。

## 布局

缓存根目录是 `cacheDir` 选项的值。

```text
<cacheDir>/
├── csv/<ref>/<locale>/<sheet>.csv
└── modules/<sheet>.<locale>.<ref>.<key>.js
```

`<ref>` 与 `<locale>` 在路径中做 URL 编码。CSV 与模块都带语种，同一个 `ref` 下构建多个语种不会互相覆盖。

## 键

`<key>` 由表名、`ref`、语种、CSV 内容哈希与规则算出，取 sha256 的前 12 位十六进制。CSV 内容进入键，内容变化就得到新的模块文件名。

规则的写法不影响键：对象字段的顺序、`onlyRowKeys` 的顺序、数字与字符串写法都得到同一个键。

## 复用与请求

每次构建先确定 CSV，再查模块。

CSV 缓存可用时直接读取，否则重新请求。

随后算键并查模块：模块文件存在且能解析出 `origin` 与 `data` 时直接复用，解析与裁剪跳过；不存在或解析失败时重新解析与裁剪，并写入模块。

CSV 缓存可用且模块存在时，这次构建不发请求。

## 新鲜度

CSV 缓存可用是指未过期，或 `ref` 是 `HEAD` 以外的值。

`ref` 为 `HEAD` 时，CSV 缓存按 `maxAge` 过期。

`ref` 是 `HEAD` 以外的值时，缓存不再按时间更新，即使 `maxAge` 更短。这个值可能是分支名，仍会移动；固定的是缓存策略，不是上游内容。

## 清理

缓存不删除旧文件。同一次构建中，两个入口可以用不同规则导入同一张表；按表名删除旧键会删掉另一个入口仍在使用的模块。删除整个目录后，下次构建重新请求。
