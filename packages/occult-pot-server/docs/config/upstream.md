# 出站调用

访问腾讯文档的节奏、缓存与过期判定。上游本身的限制与失败如何呈现见 [与腾讯文档通讯](../api/upstream/README.md) 和 [错误处理](../api/errors.md)。

## OPS_UPSTREAM_MAX_PER_INTERVAL

- 类型：`整数`
- 默认值：`10`
- 每个间隔允许的调用数，所有出站调用共用这一份配额。十次每三秒是原客户端脚本的节奏；平台另外按天限次（超级会员两万次），所以这个窗口管的是突发，不是每日预算。

## OPS_UPSTREAM_INTERVAL_MS

- 类型：`时长（毫秒）`
- 默认值：`3000`
- 上面那些调用被均匀铺开的间隔。一次调用占一枚令牌，失败不会被再次送出，所以这个窗口同时也就是对外 `Retry-After` 的时长。

## OPS_UPSTREAM_TIMEOUT_MS

- 类型：`时长（毫秒）`
- 默认值：`10000`
- 一次调用的上限，连接、响应头与响应体一起算。

## OPS_UPSTREAM_CACHE_TTL

- 类型：`时长（毫秒）`
- 默认值：`30000`
- 读取在多久之内直接答缓存。读取总是拉整张表，所以这个有效期是唯一的陈旧度控制；读表失败而缓存非空时，用缓存里的快照回答并记一条 warning。

## OPS_UPSTREAM_STALE_AFTER_MS

- 类型：`时长（毫秒）`
- 默认值：`10800000`（3 小时）
- 一次读取之后，`最后一次进岛时间` 比这个还旧的行会被从表里删掉并从缓存里去掉，根本不是合法罐子的行同样如此。
