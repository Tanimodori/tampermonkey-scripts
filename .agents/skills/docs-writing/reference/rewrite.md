# 重写与审阅

## 事实冻结

重写前先列事实表，不先写句子。每行给出事实、证据与读者后果。

| 事实                                                | 证据           | 读者后果                       |
| --------------------------------------------------- | -------------- | ------------------------------ |
| 端点上的 `timeoutMs` 优先于 `CallOptions.timeoutMs` | 源码与测试位置 | 端点可以覆盖这条调用的默认时限 |

- 事实只收公开契约、默认值、优先级、错误码、限制与用法。
- 证据写到文件与行。测试优先于注释；注释与实现冲突时以测试和实现为准。
- 没有证据的句子不写。写不准的先读源码或跑测试。
- 设计取舍另列一栏或另开一节，只有改变用法时才进正文。

## 读者问题

定三到五个读者读完后要能直接回答的问题。章节按问题排，不按源码文件、模块或实现阶段排。

## 提纲

- 每个问题对应一节，节内先给结论，再给契约或规则。
- 同一事实只安排一处，其他节用描述性链接指向它。
- 公开契约与最小装配放在行为规则之前，行为规则放在扩展点之前。
- 范围大时先让审阅者看事实表与提纲，再写成稿。

## 写作

- 先写公开契约与最小装配，再写行为规则，最后写扩展点与限制。
- 每写完一段回查事实表，句子必须能落到某一行事实。
- 源码注释里的理由、变更史与内部机制不进入正文。

## 独立审阅

作者与审阅者必须是两个独立上下文。作者完成初稿后，把成稿、事实表、读者问题与审阅项交给另一个代理；审阅者不参与写作，也不接受作者的口头解释。审阅者只报告，不改稿；作者按报告修订，不自行判定通过。

审阅提示词需要自包含，包含四项：文档路径、事实表路径或全文、读者问题、审阅项。

```text
你是这份文档的独立审阅者。只依据下列材料判断，不推测作者意图，不修改文档。
文档：${docPath}
事实表：${factTable}
读者问题：${readerQuestions}
审阅项：${reviewItems}
逐项输出：编号 / 通过或不通过 / 原文位置 / 依据。
```

## 审阅项

1. 读者任务：每个读者问题都能在正文找到直接答案。
2. 事实与证据：每个行为陈述都能在事实表中找到证据。
3. 边界：没有内部调用链、内部辅助函数、源码路径、变更史与实现理由；行为事实不写成限制。
4. 结构：章节按读者任务排，每节只回答一个问题；字段能承担的内容不单设一节。
5. 去重：同一事实只出现一处；错误处理只在失败节写。
6. 标识符：正文提到的导出标识符在代码中存在；内部标识符只作为扩展点出现。
7. 默认值与优先级：默认值、覆盖顺序与本文档负责的错误码完整，且与源码一致。
8. 用语：陈述句，无元叙述，无计数修辞，术语统一；不写常识性结论。
9. 代码块：完整合法，注释只说明是什么。
10. 交叉引用与链接：正文没有堆叠的「见某文档」；链接可达，链接文字与目标章节一致。

审阅结果只有通过与不通过。每一项都要给出依据，通过项也一样。不通过必须给出可定位的原文与依据，不用「建议」代替不通过。
