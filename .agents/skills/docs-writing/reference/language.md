# 语法与用语

## 用词和句子

- 术语与缩写首次出现时说明，避免读者不懂的行话。
- 字段、常量、类型、函数名保持代码形态不翻译，意义不明时才解释。
- 统一词汇表，不硬译英文词，一个概念只用一个术语，不允许近义词在不同文件间漂移。
- 不自造术语或缩写。术语要能对应源码里的标识符或一个具体动作；网络请求写「请求」，不写「取数」，同一个动作全文只用一个词。
- 修饰语要有对照。写 `Error` 就写 `Error`，不写「普通 `Error`」或「异常 `Error`」，这两个修饰都没有对照；需要区分类型时写出判别依据，例如 `isApiError`。
- 不复述签名与类型。代码块已经给出参数、返回值与可选性，正文只写代码看不出的行为、默认值、顺序、失败与限制；「接收 X，返回 Y」这类句子删掉。
- 不写读者无法据此行动或判断的句子。占位提示只留在范本里，成稿中不保留。
- 不写元叙述（「本节」「如上所述」）与闲话。
- 用主动语态、短句。
- 使用陈述句，不用口语化表达，不加语气加重。
- 不把需求方口吻的句子写进文档，约束改写成事实陈述。
- 避开数词枚举修辞（「一个…两个…」），用名称指称，例如标识符、类型名、`Raw` 后缀。

## 标点

中文行文少用冒号、分号、破折号。

- 顺接或转折的分句用逗号加连词连接。
- 意思说完用句号收束。
- 总-分结构中的冒号改成「为」「是」「有」「包括」等。
- 列表子项开头用冒号介绍重点时，整个列表风格统一，要么全部使用冒号要么都不用。

## Markdown 结构

### 占位符

- 尖括号内只放 kebab-case 或 camelCase 标识符，单字占位符用小写，例如 `<sheet>`、`<cacheDir>`、`<viteCacheDir>`。
- 不写带空格的词组与 PascalCase，例如 `<vite cacheDir>`、`<Sheet>`。
- 占位符指代什么在正文用一句话说明。

### 代码块与注释

- 模块级注释描述模块整体负责范围与大致内容。
- 类型/对象注释用一句话描述它是什么，例如「用于 XXX 的 YYY」。
- 字段注释用一个短语描述它是什么，例如「用户名」「API 接口地址」。默认值、优先级与条件行为不写入注释，放在正文的行为节。
- 函数内分节注释在小节开头写这一小节整体要做什么，例如「获取数据」「渲染结果」。
- 函数内做法注释在做法不显而易见时写清楚这里为什么这么做，例如「只能从这里获取数据」。
- 注释说明是什么，或在不显而易见时说明为什么这样做，不复述代码本身。可选性由 `?` 表达，不在注释里声明。测试或 lint 专用情形（如 `_` 前缀豁免）与「由谁填充」之类的机制叙述不进注释，必要时移到正文。
- 结构事实（接口、类型、类字段、配置）与公开面用带 `/**/` 注释的代码块呈现，含义由注释承载，不用散文逐字段复述。
- 代码片段必须完整合法，避免格式化器重排后读起来非法。
- 占位与插值统一使用 `${var}` 形式，真实代码语法除外。

### 链接

- 交叉引用使用描述性链接。
- 跨文档引用最小化，只有综述外链子模块，详细章节不随手引用。
- 正文不写「xxx 见 yyy」式指引。归属关系由入口文档的索引承担。
- 库与工具的选项旁附官方参考链接。
- 外链清单按主题分组，每组只给入口链接，同一对象的不同接口只保留有代表性的几个。

### 常量表

常量表覆盖配置文件、错误码与环境变量。

- 保留硬编码常量类信息，例如配置项名称与默认值、错误码与状态码、协议关键字。
- 环境变量完整清单放在 `.env` 文件里，手册只给概览，例如说明本节变量以某个前缀开头。
- 配置项作用集中到配置参考文件；没有单独的配置参考文件时，默认值与覆盖顺序写进行为节。各文档只保留与自身主题相关的配置表，列出名称与默认值，不写散文式解释。
- 单元格内容多而长的表格改成列表，或缩减内容后挪到别处。
- 错误码、取值、范围外清单等枚举用列表表达，不用代码块。
- 包含关系按从高到低列成列表，例如配置来源的优先级。
