# 落地形态

读者与形态通常绑定，读者决定详略、取舍与语气。动笔前先回答读者是谁、要完成什么、已掌握什么背景、需要知道什么，并检查读者与形态是否相符。

只为一个读者写作，读者多于一类时拆成不同文档，或在文档内清晰分节。同一种内容只出现在最合适的形态里，形态混杂时拆分到不同文件或不同章节，用户文档不复述代码，注释不承担用户指南。

## README

- 面向用户编写，侧重点为项目做什么、需要配置什么、怎么使用，不写内部实现。
- 包的入口文档，给出定位、索引与指向子文档的链接，不承载子模块细节。

## FAQ

- 面向维护者编写，侧重点为常见问题的直接答案与排查线索，不写完整教程。
- 以问答组织，回答围绕问题本身，细节链接到归属文档。

## 详细设计

- 面向开发者编写，侧重点为组成、责任边界与契约，不写用户指南与宣传文案。

## 包与 API 参考

- 面向下游包作者与使用者编写。前者声明 `Endpoint`、写适配器与校验槽，后者用 `createCall` 创建调用函数、替换 `transport`、处理失败。
- 侧重点为公开契约、默认行为、优先级、失败分类与最小装配示例，目标是让读者把包接进自己的代码。
- 开头一句写这个包或这篇文档是什么，不单设定位节。章节按读者任务组织，常用顺序为公开契约、最小装配、行为规则、当前限制。一个主题一份文档，不按源码模块拆。
- 扩展点写进公开契约或行为规则，不单设一节。
- 当前限制只写已确认、读者会撞上的事实；没有就不写。
- 公开标识符用带 `/**/` 注释的代码块呈现，字段与签名由注释说明，不用散文逐项复述。
- 行为规则按主题分节。默认值与覆盖顺序写在各节，错误码与错误字段集中在失败节。
- 设计取舍只在改变读者用法时写，集中到一处并说明它影响哪个选择；其余留在设计文档或源码注释。
- 不写内部调用链、内部辅助函数、源码路径、变更史与实现理由。
- 跨文档引用只由入口文档承担，单篇参考文档不写「见某文档」。

## 运维手册

- 面向维护者编写，侧重点为部署步骤、运行参数、监控与故障处理，不写内部实现。

## 常用类型与范本

按文档的实际类型选范本。范本只提供结构，正文事实来自事实表。

| 类型         | 读者           | 写什么                               | 范本                                 |
| ------------ | -------------- | ------------------------------------ | ------------------------------------ |
| README       | 使用者         | 一句是什么、能力、最小用法、文档索引 | [README](../exemplars/README.md)     |
| 端点表       | API 使用者     | 端点一览、参数、正常答复             | [endpoint](../exemplars/endpoint.md) |
| 统一错误处理 | 调用方         | 错误类、错误码、字段                 | [error](../exemplars/error.md)       |
| 对象与类型   | 使用者         | 对象是什么、公开契约、行为、边界     | [class](../exemplars/class.md)       |
| 功能或切面   | 使用者与维护者 | 整体结论、逐部分或逐维度、注意事项   | [topic](../exemplars/topic.md)       |
| 日常开发     | 贡献者         | 前置、命令、测试、注意事项           | [develop](../exemplars/develop.md)   |

README 是入口文档，索引由它承担。端点表、统一错误处理、对象与类型是单篇参考文档，彼此不写「见某文档」。
