# 落地形态

读者与形态通常绑定，读者决定详略、取舍与语气。动笔前先回答读者是谁、要完成什么、已掌握什么背景、需要知道什么，并检查读者与形态是否相符。

只为一个读者写作，读者多于一类时拆成不同文档，或在文档内清晰分节。同一种内容只出现在最合适的形态里，形态混杂时拆分到不同文件或不同章节，用户文档不复述代码，注释不承担用户指南。

## README

- 面向用户编写，侧重点为项目做什么、需要配置什么、怎么使用，不写内部实现。
- 包的入口文档，给出定位、索引与指向子文档的链接，不承载子模块细节。

## FAQ

- 面向维护者编写，侧重点为常见问题的直接答案与排查线索，不写完整教程。
- 以问答组织，回答围绕问题本身，细节链接到归属文档。

## 详细设计

- 面向开发者编写，侧重点为组成、责任边界与契约，不写用户指南与宣传文案。

## 运维手册

- 面向维护者编写，侧重点为部署步骤、运行参数、监控与故障处理，不写内部实现。
