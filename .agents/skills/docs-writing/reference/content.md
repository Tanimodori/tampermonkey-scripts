# 内容

先判断主题属于哪一类，再决定写什么。

- 整体概述写整体由哪些部分组成、如何配合，可以链接到各子模块文档。
- 单一对象写对象是什么、由什么构成。
- 对象的某个维度写对象的一个特性或流程。

## 取舍

- 重点写服务或工具做什么、使用者需要配置什么，不写具体怎么做。
- 不写方法名与调用链、源码路径、内部流程与模块划分、内部数据结构、实现细节、覆盖率与路线图。
- 不复述代码，不写思维链。
- 不出现真实生产或测试环境地址、账号与凭据，只使用占位符与保留示例地址。
- 未完成或未验证的内容写成简短的「当前限制」事实段落。
- 不硬编码版本号，此类约束写成「与仓库其余部分保持一致」。
- 不写防御性内容。边界写成责任范围，不写「不做什么」、不会发生的事与假设场景。
- 不把用户提示词原文写进文档，约束改写成事实陈述。
- 能从类型声明看出的 optional 不在正文列举。
- 内容尽量压缩，只保留读者需要的事实。

## 主题边界

- 每份文档只围绕自己的主题，越界内容压缩为一句结论并附指向归属文档的链接。
- 同一件事只写一处，同一对象、结构、目录不重复描述。
