# 与腾讯文档通讯

服务通过腾讯文档 Open API 读写在线智能表，腾讯文档是数据的权威来源。按领域分三份：[子表](file.md)、[记录](record.md)、[凭据](token.md)。

## 文档坐标

`fileID` 是 Open API 的编号，不是浏览器地址栏里的表格链接。两者都能从一条已授权的调用读到，由分享链接反推的方法见[官方转换工具](https://docs.qq.com/open/document/app/openapi/v2/file/util/converter.html)。

坐标与凭据只放在环境变量里：生产是部署目录的 `.env.production.local`，测试文档是 `.env.test-api.local`，容器中由 compose 注入。启动时会核对子表属于该文档，不匹配则拒绝启动；上游当时连不上或被限流，则带着未就绪状态启动，由后续请求再核对一次。变量清单与默认值见 [配置：腾讯文档](../../config/docs.md)。

## 凭据

访问文档需要一个 access token，以及配套的 `client_id` 与 `open_id`。access token 有效期 30 天，refresh token 1 年，换取与刷新都必须由后台服务发起。

环境变量中的值是初始值：Redis 中已保存且未过期的 token 优先使用，刷新得到的结果写回 Redis。启动时校验凭据，被拒时服务以未就绪状态启动，就绪探针说明原因；进入有效期最后 3 天时记录一条 warning，过期后就绪状态变为 `offline`，上游调用返回鉴权失败。轮换凭据的方式是修改环境变量并重启。

两个凭据端点见 [凭据与用户信息](token.md)。日志只记录 token 的长度、到期时刻与校验结果，见 [日志](../../deploy/logging.md)。

## 频率与次数

腾讯文档按频率与每日次数限制调用：每个 `fileID` 每分钟 150 次，每个 `openID` 每分钟 300 次，超级会员账号每日 20000 次。服务把出站调用均匀铺开，默认每 3 秒最多 10 次；长期用量主要由缓存有效期决定。

传输层失败（连不上、超时、HTTP 5xx、限流、正文无法解析为 JSON）直接返回失败：一次调用就是一次往返，服务端不再重发，写入失败由客户端自己再写一遍。对外错误码见 [错误处理](../errors.md)，节奏的配置见 [配置：出站调用](../../config/upstream.md)。

## 响应信封

每个回答形如 `{ ret, msg, data }`：`ret` 是结论（`0` 为成功），`msg` 是它的措辞，`data` 装内容。

传输层的结论优先于 `ret`：服务内部错误 `400010` 是带着 HTTP 500 来的，429 无论从哪个端点出现都是限流。

`data` 按调用的关键字分节，例如查询记录的回答位于 `data.getRecords`。两个不分节的端点各自的形状见 [删除记录](record.md#删除记录) 与 [获取用户信息](token.md#获取用户信息)。

回答中会有本服务不读的附加字段（作者列、`autoRawRecords` 一类），一律原样保留，因此报错里引用的正文与上游发出的一致。

## 错误码

上游的业务返回码与它们的含义见 [常见错误码](https://docs.qq.com/open/document/app/openapi/v3/common/code.html)；本服务对外回答的错误码见 [错误处理](../errors.md)。
