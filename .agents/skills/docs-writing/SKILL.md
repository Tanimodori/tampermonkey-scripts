# 写作目的

文档与注释都写给特定读者，目的是帮助读者完成自己的任务，不是解释一切。动笔前先完成读者与形态、内容、结构的判断，再考虑怎么写。

# 写作流程

1. 明确读者与落地形态。读者与形态通常绑定，读者决定详略与取舍，形态决定内容放在哪里、写多细，见 [落地形态](reference/form.md)。
2. 明确内容。内容是整体概述、单一对象还是对象的某个维度，由此划定主题边界，见 [内容](reference/content.md)。
3. 判断叙述整体结构。对象型先写是什么与构成，特性型先把整体讲清楚，再安排次要内容，见 [叙述整体结构](reference/structure.md)。
4. 按语法要求写出。陈述句行文，标识符保持代码形态，术语统一，标点符合中文习惯，代码块与注释、链接、常量表按结构规范写，见 [语法与用语](reference/language.md)。

# 通用要求

- 不执行版本控制操作，改动留在工作区。
- 有疑问先向用户提问，不自行猜测。
- 统一复查全部描述的风格，而不是只修改被点名的位置。
- 修订后执行格式化检查。
- 复查相对链接与外部链接是否有效，新增链接前先核验可达性。
- 按交付物标准校对，笔误要改，步骤数与列表数量一致，标题与链接文字符合目标文件与章节，正文提到的标识符必须在代码中存在。
- 整文件重写后读回结果并检查 `git diff`，散文部分用 `git diff --word-diff=plain` 确认只落入预期改动。
- 注释与文档跟实现保持同步。重构后全仓搜索过时术语与引用，逐处改写为新实现口径。
