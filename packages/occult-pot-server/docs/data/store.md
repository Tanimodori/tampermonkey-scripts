# 存储设计

罐子列表、腾讯文档凭据与调用者的访问计数都放在 Redis 里；腾讯文档在线表格始终是数据的权威来源。

## 缓存行为

- 缓存未超过有效期时，读取请求直接使用缓存；超过有效期才读取腾讯文档，读到的整份列表替换缓存。
- 读取腾讯文档失败时，只要缓存中有数据就返回缓存内容并记录一条 warning；缓存为空时把失败返回给调用方。
- 写入请求先落到腾讯文档，成功后再把这条记录追加进缓存，因此写入后的列表读取能看到它且不会回源。腾讯文档拒绝写入时请求失败，缓存不变。
- 缓存按追加处理，不合并重复项：同一个罐子提交两次就是两条记录。
- 回源期间的写入会等待本次回源结束，避免两边互相覆盖。

## 凭据与调用者数据

腾讯文档凭据也保存在 Redis 中，因此刷新得到的 token 在进程重启后继续有效；`client_secret` 只从环境读取。调用者的访问计数按客户端 IP 记录，用于限流统计，探针请求不计入；限流计数同样存放在 Redis 中，多实例共享同一份窗口。

## 单实例与多实例

状态与限流计数在 Redis 中共享，重启不丢数据，多副本看到同一份罐子列表，写入也不需要跨实例协调。出站调用队列是每进程一份，多副本会成倍放大腾讯文档的调用量，因此部署建议单实例。

## 配置

| 变量                          | 默认值                             |
| ----------------------------- | ---------------------------------- |
| `OPS_SERVER_REDIS_URL`        | —（未设置时使用进程内 Redis mock） |
| `OPS_SERVER_REDIS_PASSWORD`   | —                                  |
| `OPS_UPSTREAM_CACHE_TTL`      | `30000`                            |
| `OPS_UPSTREAM_STALE_AFTER_MS` | `10800000`                         |
